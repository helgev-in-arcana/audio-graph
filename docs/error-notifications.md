# エラーの保持と画面表示

エラー内容を現在の文書に所属させ、エディターを閉じている間も保持する。
手動でエディターを開くと、保存状態・グラフ・音声処理のエラーを確認できる。
nice-plugの変更、DAWへの自動表示要求、OSのポップアップは含まない。

## 担当と公開API

| API | 担当 |
| --- | --- |
| `Shared::report_error(document, source, message)` | 文書世代を確認し、発生元の最新メッセージを保持する |
| `Shared::clear_error(document, source)` | 指定した文書・発生元の通知を解除する |
| `Shared::error_message(source)` | 画面の有無によらず、現在のメッセージを取得する |

上記は非音声スレッド用。同じ発生元・内容の繰り返しではメッセージを作り直さず、
件数も増やさない。履歴や無制限のキューは持たない。
文書の置き換えで通知を破棄し、旧文書のworker・音声側から遅れて到着した報告は捨てる。

## 接続しているエラー

- `State`: 保存されたグラフを読み取れない場合。既存のG2画面に理由を表示する。
- `Graph`: コンパイル、処理構成の準備、メタデータ更新の失敗。既存のコンパイルエラー表示と同じ文章は重ねて表示しない。
- `Processing`: 処理失敗またはイベントバッファーの不足を検出し、処理をリセットした場合。

音声処理側は、エラー時だけ固定サイズの`AtomicU64`へ実行対象の文書世代を記録する。
既存の主スレッドtickで表示用の文章へ変換するため、通知に次の音声ブロックは必要ない。
正常な音声ブロックに通知用の割り当て・ロック・ホスト呼び出しは追加しない。
主スレッド側の配送は既存tickの対応範囲に従う。

処理エラーの通知は、成功した再activate、文書の置き換え、または明示的な通知解除まで保持する。
コンパイル成功時にはグラフのエラー通知を解除する。

## 復旧・保存との分担

通知を保持・解除しても、エラーの復旧方針や保存の可否は変えない。
G2の原本保持、消音、編集・保存の保留は既存の復元処理が決める。
通常のエラー通知が残っていても、グラフの保存は可能。

エラーを自動で収集するログ捕捉機構ではない。通知する箇所を明示して共通APIへ接続する。
自動でDAWにエディターを開かせる案は別の保留ブランチで管理し、この機能の依存にはしない。
